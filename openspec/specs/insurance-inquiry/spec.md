# 顧客問い合わせ受付・管理（insurance-inquiry）

## Purpose

保険契約に関する顧客からの問い合わせを、受付経路を問わず一元的に受け付け、対応状況を追跡し、回答完了まで管理する機能。応答期限の遵守と対応記録の保全を通じて、顧客対応品質と監査対応の両立を担う。

## 業務処理概要

保険契約者・被保険者・保険金受取人・代理店から寄せられる問い合わせは、電話・Webフォーム・メール・代理店経由と経路が多岐にわたる。従来は経路ごとに記録が分散し、対応漏れ・重複対応・応答期限の超過が発生していた。本機能は、経路によらず問い合わせを同一の管理単位として受け付け、対応状況を可視化することでこれを防ぐ。

利用者は、コールセンターのオペレーター（受付・一次回答）、契約サービス部門の担当者（照会・変更対応）、苦情対応部門（エスカレーション対応）、および管理者（応答期限の監視・監査対応）である。顧客自身はWebフォームからの登録および受付番号による状況照会の範囲で利用する。

問い合わせは内容により扱いが異なる。契約内容の照会や契約者情報の変更は本人確認の成立を前提とし、給付金・保険金の請求手続に関する問い合わせは健康状態に関する情報を含みうるため、記録・参照の統制を他の種別より厳格に扱う。苦情に該当する問い合わせは、応答期限と保持期間の双方で別基準を適用する。

**用語定義**

| 用語 | 定義 |
| --- | --- |
| 問い合わせ | 顧客から寄せられた1件の要求。受付から完了までを1つの管理単位として扱う |
| 受付番号 | 問い合わせ1件に対して発行される識別子。顧客への案内および内部追跡に用いる |
| 本人確認 | 証券番号・生年月日・氏名の3点が契約情報と一致することの確認 |
| 苦情 | 当社の対応・商品・手続に対する不満の表明を含む問い合わせ。種別として明示的に区分する |
| 初回応答 | 受付後、顧客に対して行う最初の実質的な回答または状況連絡 |
| 営業日 | 土日祝日および当社休業日を除く日 |

## 業務目線の入出力

- **入力**：問い合わせ者の属性（契約者・被保険者・受取人・代理店の別）、本人確認情報、受付経路、問い合わせ種別、問い合わせ内容、関連する契約の識別情報
- **出力**：受付番号の発行、対応担当部門への割り当て、対応状況（ステータス）の記録、初回応答期限の設定、対応履歴の蓄積

## Requirements

### Requirement: 本人確認の成立

- 【SHALL】契約内容の照会または契約者情報の変更を伴う問い合わせは、本人確認が成立していなければ対応を開始してはならない。
- 【SHALL】本人確認は、証券番号・生年月日・氏名の3点が契約情報と一致したときに成立しなければならない。
- 【SHALL NOT】本人確認が成立していない問い合わせに対して、契約内容を回答してはならない。

代理人による連絡の判定基準および代理権の確認手順は、本機能の対象外とし、別途の業務手続に委ねる。

#### Scenario: 正常系 - 3点一致による成立

- **WHEN** 証券番号・生年月日・氏名が契約情報と一致する
- **THEN** 本人確認が成立した状態として記録される
- **AND** 対応を開始できる

#### Scenario: 異常系 - 一部不一致

- **WHEN** 3点のうち1点以上が契約情報と一致しない
- **THEN** 本人確認は成立せず、契約内容は回答されない
- **AND** 本人確認未成立として記録される

#### Scenario: 境界値 - 本人確認を要しない種別

- **WHEN** 問い合わせ種別が一般的な商品説明の求めであり、契約内容の照会を含まない
- **THEN** 本人確認の成立を待たずに対応を開始できる

### Requirement: 問い合わせステータスの遷移

- 【SHALL】問い合わせは、受付・対応中・保留・エスカレーション・回答済・完了のいずれかの状態を持たなければならない。
- 【SHALL】新規に受け付けた問い合わせは、受付の状態で登録されなければならない。
- 【SHALL NOT】完了した問い合わせの状態を、完了以外の状態へ戻してはならない。
- 【SHALL NOT】回答済を経ずに完了へ遷移してはならない。

再度の問い合わせが寄せられた場合は、完了した問い合わせを再開せず、新規の問い合わせとして受け付け、元の受付番号を関連情報として保持する。

#### Scenario: 正常系 - 標準的な遷移

- **WHEN** 受付状態の問い合わせに担当者が着手し、回答を行い、顧客の了解を得る
- **THEN** 受付 → 対応中 → 回答済 → 完了 の順に状態が遷移する

#### Scenario: 異常系 - 完了からの差し戻し

- **WHEN** 完了状態の問い合わせを対応中へ変更しようとする
- **THEN** 状態の変更が拒否される

#### Scenario: 境界値 - 回答済を経ない完了

- **WHEN** 対応中の問い合わせを回答済を経ずに完了へ変更しようとする
- **THEN** 状態の変更が拒否される

### Requirement: 初回応答期限

- 【SHALL】問い合わせには、受付日を起算日とする初回応答期限が設定されなければならない。
- 【SHALL】初回応答期限は、受付日から3営業日後としなければならない。ただし種別が苦情である問い合わせは1営業日後としなければならない。
- 【SHALL】初回応答期限を超過し、かつ初回応答が記録されていない問い合わせは、超過状態として識別できなければならない。

営業日の判定に用いる休業日暦の管理方法は本機能の対象外とし、共通機能に委ねる。

#### Scenario: 正常系 - 通常種別の期限設定

- **WHEN** 種別が契約内容照会の問い合わせを受け付ける
- **THEN** 受付日から3営業日後が初回応答期限として設定される

#### Scenario: 正常系 - 苦情の期限設定

- **WHEN** 種別が苦情の問い合わせを受け付ける
- **THEN** 受付日から1営業日後が初回応答期限として設定される

#### Scenario: 境界値 - 期限当日中の応答

- **WHEN** 初回応答期限の当日に初回応答が記録される
- **THEN** 期限内の応答として扱われ、超過状態にならない

#### Scenario: 異常系 - 期限超過

- **WHEN** 初回応答期限を過ぎても初回応答が記録されていない
- **THEN** 当該問い合わせが超過状態として識別される

### Requirement: 対応記録の保持

- 【SHALL】問い合わせの受付内容・対応履歴・回答内容は、完了日から5年間、参照可能な状態で保持されなければならない。ただし種別が苦情である問い合わせは10年間保持されなければならない。
- 【SHALL NOT】保持期間内の問い合わせ記録を、物理的に消去してはならない。

保持期間を経過した記録の取り扱いは、アーカイブおよび廃棄の業務手続に委ねる。実案件における保持年数は法務確認を要する。

#### Scenario: 正常系 - 保持期間内の参照

- **WHEN** 完了から5年を経過していない問い合わせを参照する
- **THEN** 受付内容・対応履歴・回答内容が参照できる

#### Scenario: 正常系 - 苦情の保持

- **WHEN** 種別が苦情の問い合わせが完了する
- **THEN** 完了日から10年間の保持期間が設定される

#### Scenario: 異常系 - 保持期間内の消去

- **WHEN** 保持期間内の問い合わせ記録に対して削除が要求される
- **THEN** 物理的な消去は行われず、参照可能な状態が維持される

### Requirement: 要配慮情報を含む問い合わせの識別

- 【SHALL】給付金または保険金の請求手続に関する問い合わせは、要配慮情報を含みうる問い合わせとして識別されなければならない。
- 【SHALL】要配慮情報を含みうる問い合わせに対する参照操作は、操作者と操作日時が記録されなければならない。

具体的な暗号化方式・マスキング規則・権限設計はセキュリティ横断Spec（SPEC-104）に委ねる。本Requirementは識別と記録の必要性のみを定める。

#### Scenario: 正常系 - 請求手続の識別

- **WHEN** 種別が給付金・保険金の請求手続である問い合わせを受け付ける
- **THEN** 要配慮情報を含みうる問い合わせとして識別される

#### Scenario: 正常系 - 参照操作の記録

- **WHEN** 要配慮情報を含みうる問い合わせが参照される
- **THEN** 操作者と操作日時が記録される
