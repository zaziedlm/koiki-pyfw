## 3. 各候補の詳細

### 3.1 `tests/unit/test_hello.py` 🔴 今すぐ

内容: `def test_hello(): assert True` のみ。

理由: 実際の検証をまったく行わないプレースホルダー。pytest collect に含まれるため、テスト品質の見た目を下げる。  
確認事項: なし。  
削除方法: そのまま `git rm tests/unit/test_hello.py` して次の適切なコミットに含める。

---

### 3.2 PyJWT 移行検証テスト 🟠 確認後に削除

対象:

- `tests/unit/test_pyjwt_migration.py` — HS256/RS256 移行挙動の一時検証 (T1〜T8)
- `tests/e2e/test_pyjwt_e2e.py` — Docker 上の API 向け移行 E2E

背景: v0.7.0 で `passlib` を runtime dependency から削除し、PyJWT へ移行済み。これらは移行プロセスの一時的な検証テストとして追加された。

確認事項:

```powershell
uv run pytest tests/unit/test_pyjwt_migration.py -v --tb=short
```

全 PASS を確認したうえで「移行後の挙動が現在も成立している」と記録してから削除する。  
削除後は `components/libkoiki/tests/` 内の既存 auth / security テストで十分に回帰カバーされていることを確認する。

## 4. 削除しないもの（意図的に維持）

以下は DM-12 の棚卸し判断で「互換維持」または「予約領域」とされており、v0.8 以降も維持する。

| 対象 | 理由 |
|---|---|
| `app/__init__.py` / `app/main.py` | `app.main:app` 互換 wrapper。廃止時期は別途判断。 |
| `apps/` skeleton（`asgi.py`, `models/sample.py` 等） | downstream 向け予約領域・雛形。README の説明を維持。 |
| `tests/unit/test_apps_composition.py` | apps/ 合成 smoke テスト。現役。 |
| `docs/backend-audit/` (LOG-02〜LOG-12 等) | ロギング監査の設計根拠・セキュリティ方針として参照価値がある。 |
| `ops/` | セキュリティ権限管理テスト・スクリプト群。現役利用の可能性あり。 |

## 5. v0.8 準備 PR での推奨作業順

1. `tests/unit/test_hello.py` を削除する（単独コミットでも可）。
2. `uv run pytest tests/unit/test_pyjwt_migration.py -v` で PASS を確認してから削除。
3. v0.8 準備 PR を1本立てて、3.3〜3.5 の対象をまとめて `git rm` する。
4. PR の説明に「削除理由: v0.7.0 完了を根拠とする計画的 docs 整理」と記載する。
5. `docs/archive/` は後続 PR で任意対応とする。
