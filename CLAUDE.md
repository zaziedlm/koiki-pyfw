Claude Code notes:

- Project skill discovery lives under `.claude/skills/`.
- Canonical skill content lives under `docs/agent/skills/`.
- Use canonical docs and skills as the source of truth.
- `.claude/skills/openspec-*` are generated by `openspec init` / `openspec update`. They are tool-managed, have no canonical copy under `docs/agent/skills/`, and must not be hand-edited.
- When they conflict, `koiki-spec-authoring` takes precedence over `openspec-*` on notation and content conventions; `openspec-*` remains authoritative on workflow and CLI usage.
- OpenSpec here uses the OPSX experimental workflow (`.claude/skills/openspec-*`, `.claude/commands/opsx/*`, `openspec/config.yaml`). There is no `openspec/AGENTS.md` — that was the older, now-obsolete single-file workflow, and current OpenSpec CLI treats it as a legacy file to remove if found. Project-specific spec rules belong in `openspec/config.yaml`.
